# L04 实践操作手册｜委托 Codex 执行一次最小变更

> 本讲约 120～180 分钟。具体原理见[辅导资料](./辅导资料.md)。所有命令默认在个人课程练习仓库根目录的 PowerShell 中运行。

## 今天只走一条授权链

```text
Ticket A：补齐 Workbench V0
    ↓ 非执行者独立复验并接受
Ticket B：V0 读取 L03 Spec，调用 Codex 实现库存导出
    ↓ 独立复验 CSV、状态和范围
具名接受或打回返工
```

最终交付：

- A 的建设合同、范围内 Diff、前后检查和独立接受记录；
- B 的任务编号、候选目录、实际修改、检查报告和人工决定；
- 可读取的库存 CSV；
- 一条失败或风险如何推动返工的记录。

没有非执行者接受 A 时，不启动 B。自动检查通过时，B 仍停在等待人工审核。

![Ticket A 先验收工作台，Ticket B 再交付库存导出](./assets/diagrams/01-two-tickets.png)

*按箭头读取唯一顺序：先直接监督 Codex 建设 Ticket A，再由非执行者复验并接受具体 V0 版本；只有随后才能启动 Ticket B。B 仍要在同一候选上检查 CSV、库存状态和文件范围，最后由人单独接受或打回。A 与 B 不能合并成一次自动通过。*

---

## 本手册中的 Prompt 和 Skill 怎么用

### Prompt：在对应阶段复制后发送

`prompts/` 中的文件分别服务 A 建设、A 独立验收、B 执行和 B 独立复验。打开当前阶段对应文件，复制正文，替换真实任务编号、姓名和路径后发送；不要一次粘贴四份 Prompt，也不要把它们当成终端命令。

例如，开始 A 时可以发送：

```text
请按 docs/courses/L04/prompts/01-设计能力信封并留下TicketA红灯.md 工作。
当前阶段是 Ticket A 的 V0 缺口调查。
先检查实际仓库和前序成果，不启动 Ticket B。
```

### Skill：让 Codex 读取后选择当前阶段

需要持续协助时发送：

```text
请读取并使用 docs/courses/L04/skills/controlled-delivery-handoff/SKILL.md。
当前阶段是 Ticket A 的 V0 缺口调查。
先核对已有能力、真实缺口和允许写集，不启动 Ticket B。
```

后续把“当前阶段”改成“A 的独立复验”“B 的受控执行”或“B 的独立复验”。Skill 负责保持 A、B 和审核边界，Prompt 负责交代本次输入；两者都不能代替实际人员接受任务。

只有将完整 Skill 文件夹安装到 Codex 可发现的 `.agents/skills/` 等位置后，才直接使用 `$controlled-delivery-handoff`。课程默认明确读取路径。当前机制见 [OpenAI 官方 Skill 文档](https://developers.openai.com/zh-Hans/docs/build-skills)。

## 第 1 步：一次性准备本讲记录

确认 L01～L03 的练习成果位于当前仓库，然后复制整个代码块到 PowerShell：

```powershell
& {
    $repo = git rev-parse --show-toplevel 2>$null
    if ($LASTEXITCODE -ne 0 -or -not $repo) { throw '当前目录不是 Git 练习仓库。' }
    Set-Location $repo.Trim()

    $dir = 'lesson-04-submission'
    New-Item -ItemType Directory -Path $dir -Force | Out-Null

    $contract = Join-Path $dir 'WB-L04-BOOTSTRAP.md'
    if (-not (Test-Path -LiteralPath $contract)) {
        @'
## 来源
L01～L03 的个人成果及本次 V0 缺口调查。当前已有：待调查。本轮缺少：待调查。

## 目标
补齐 Spec 绑定、受控执行、范围检查、最小 Eval、结果摘要和人工确认链。

## 非目标
Ticket A 不开发库存导出，不扩展无关平台功能。

## 约束
工作目录、允许修改文件、超时和复验命令在调查后填写。失败保留原始输出；检查通过仍等待人工审核。

## 验收用例
有效合同可绑定任务；无写集的编码请求被拒绝；失败、超时和越界留下原因；绿灯后停在待审核；控制源码变化后旧接受失效。

## 完成定义
保存实际修改、检查命令、退出码和剩余风险，由非执行者复验当前版本并具名接受。
'@ | Set-Content -LiteralPath $contract -Encoding UTF8
    }

    foreach ($name in @('A-evidence.md', 'B-evidence.md', 'handoff.md')) {
        $file = Join-Path $dir $name
        if (-not (Test-Path -LiteralPath $file)) { New-Item -ItemType File -Path $file | Out-Null }
    }

    python -X utf8 -c "import sys,workbench; from pathlib import Path; print('Python:',sys.executable); print('仓库:',Path.cwd()); print('源码:',workbench.__file__)"
    if ($LASTEXITCODE -ne 0) { throw '环境核对失败，请恢复前几讲使用的虚拟环境。' }

    foreach ($required in @('AGENTS.md', 'lesson-03-submission/FDE_SPEC.md', 'workbench/spec.py')) {
        if (-not (Test-Path -LiteralPath $required)) { throw "缺少前序成果：$required" }
    }
    Write-Host 'L04 准备完成。'
}
```

重复运行不会覆盖已有记录。

**本步通过标准：**环境和源码属于个人练习区，L02 规则、L03 Spec 和解析器都能找到。

## 第 2 步：调查 V0 缺口，完成 A 的建设合同

把下面请求发给 Codex：

```text
请只读调查当前个人研发工作台，准备 Ticket A。
读取 AGENTS.md、L01 工作台 Spec、L03 模板与解析器、现有 workbench/ 和相关测试。

逐项说明以下能力是“已有并有测试”“存在但未接通”还是“缺失”：
1. 绑定并回查 Spec；
2. 创建任务；
3. 区分只复验与调用 Codex 编码；
4. 限定工作目录、写集和超时；
5. 保存调用、输出、退出码和 Diff；
6. 越界、失败或超时停止并留证；
7. 运行最小 Eval 并生成摘要；
8. 绿灯后停在人工审核。

给出来源文件、对应测试、真实缺口和建议修改文件。先不要修改。
```

根据调查结果，修改 `lesson-04-submission/WB-L04-BOOTSTRAP.md`：

- 在“来源”写明已有能力和真实缺口；
- 在“约束”逐个列出允许修改文件、超时和检查命令；
- 在“完成定义”填写计划中的非执行者审核人；
- 不把库存导出放进 A 的范围。

运行结构检查：

第二张故意删除“完成定义”，解析器明确报告缺少章节并返回退出码 1。你的合同若得到同类错误，应先补齐合同，不得进入第 3 步。

**本步通过标准：**合同六段完整，A 的写集来自实际缺口，不使用“整个仓库”作为授权范围。

## 第 3 步：直接监督 Codex 补齐并自查 V0

此时仍由你直接监督 Codex 建设工作台，不通过工作台派发编码任务。发送：

```text
我已确认 lesson-04-submission/WB-L04-BOOTSTRAP.md。
请严格按合同补齐 Workbench V0。

先为真实缺口补测试并运行，再做最小实现，最后重跑同一检查。
已有能力只复验，不重写。越出允许文件前必须停止并说明原因。

完成后报告：
- 实际修改文件及原因；
- 实现前结果、范围内 Diff、实现后同一检查结果；
- 正常、越界、失败或超时、绿灯后待人审的证据；
- 启动命令、验证命令和剩余风险。
```

课程参考检查入口：

```powershell
python -X utf8 -m unittest tests.test_workbench tests.test_execution_streams tests.test_bootstrap_handoff -v
$LASTEXITCODE
git status --short
git diff --check
```

将实际命令、用例数、退出码、修改文件和剩余风险写入 `lesson-04-submission/A-evidence.md`。起点已经具备的能力如实写“已有能力复验”，不要破坏实现制造红灯。

![教师参考实测中的执行边界与失效检查](./assets/execution/03-control-checks.png)

*这张参考记录展示 15 项控制检查及 `OK`，覆盖越界写入、失败或超时留证、控制源码变化后旧接受失效等行为。它只能帮助你辨认应观察哪些结果；你的 A 仍须保存自己运行的命令、用例数、退出码和当前源码 Diff。*

**本步通过标准：**V0 能受控执行并留证，实际 Diff 没有越出 A 的合同。

## 第 4 步：建立 A，并由非执行者独立接受

### 4.1 启动工作台

在一个 PowerShell 终端运行并保持：

```powershell
python -X utf8 -m workbench.cli serve-workbench --host 127.0.0.1 --port 8001 --runtime-dir .runtime/l04-learning
```

打开 [工作台首页](http://127.0.0.1:8001/)。后续命令使用另一个 PowerShell，并始终使用同一个 `.runtime/l04-learning`。

### 4.2 创建 A

把姓名替换为实际构建者：

```powershell
python -X utf8 -m workbench.cli task-create `
  --runtime-dir .runtime/l04-learning `
  --requirement-id WB-L04-BOOTSTRAP `
  --request '独立复验本讲补齐的 Workbench V0' `
  --spec-path lesson-04-submission/WB-L04-BOOTSTRAP.md `
  --actor '实际构建者姓名'
```

记下返回的 A 编号。

### 4.3 交给非执行者复验

把 A 编号、合同、Diff 和 `A-evidence.md` 交给同伴。新 A 的下面命令由同伴运行：

```powershell
python -X utf8 -m workbench.cli task-run TASK-实际A编号 `
  --runtime-dir .runtime/l04-learning `
  --actor '实际复验者姓名'
```

同伴核对当前源码版本、亲自重跑第 3 步检查，然后作出决定：

```powershell
python -X utf8 -m workbench.cli task-review TASK-实际A编号 `
  --runtime-dir .runtime/l04-learning `
  --reviewer '实际复验者姓名' `
  --decision approve `
  --note '已核对当前版本、范围、命令、结果和剩余风险'
```

有缺口时把 `approve` 改为 `reject`，在 note 中写明具体问题。没有实际同伴时让 A 停在待审核，**不要继续 B**。

![工作台任务详情停在人工验收阶段](./assets/workbench/04-task-detail.png)

*看页面上方的“等待具名人审”、第 5 阶段“人工验收”和“批准完成／打回返工”按钮。下方交付摘要、核验证据和 Eval 结果只是审核材料；在审核人、理由和决定尚未填写时，任务仍未被接受。*

**本步通过标准：**A 由非执行者基于当前版本具名接受；建设者自验不能代替这一决定。

## 第 5 步：冻结 B 的输入并提交库存导出

先核对 L03 确认版 `lesson-03-submission/FDE_SPEC.md` 至少明确：

- 八列及顺序：`sku,name,site,location,lot_id,on_hand,reserved,available`；
- `available = on_hand - reserved`；
- 每条商品、仓库、仓位、批次明细独立输出；
- 按 `sku → site → location → lot_id` 排序；
- 空库存、特殊字符、文件失败和只读性；
- 实际确认人、日期和确认状态。

运行并保存输入指纹：

```powershell
python -X utf8 -m workbench.cli spec lesson-03-submission/FDE_SPEC.md
if ($LASTEXITCODE -ne 0) { throw 'L03 Spec 无效，不能启动 B。' }
Get-FileHash -Algorithm SHA256 lesson-03-submission/FDE_SPEC.md
```

确认 A 已接受后，替换编号和姓名执行：

如果 A 仍未接受，工作台必须在资格检查阶段阻断 B。下图是教师参考实测：命令尚未启动 Codex 编码，终端明确报告“工作台 Ticket A 尚未被具名接受”，退出码为 2。

等待命令结束，不要重复提交。记下 B 编号和退出码：

再查看 B：


**本步通过标准：**B 绑定已接受的 A 和同一份 L03 Spec，在隔离候选中执行，并留下真实 Diff 与命令结果。

## 第 6 步：独立复验 B 的库存导出

使用课程检查脚本验证 B 的候选。复制整个代码块，按提示输入 B 编号：

```powershell
& {
    $python = (Get-Command python).Source
    $probe = (Resolve-Path 'docs/courses/L04/scripts/check_inventory_delivery.py').Path
    $taskId = Read-Host '输入 B 任务编号'
    $taskText = & $python -X utf8 -m workbench.cli task-show $taskId --runtime-dir .runtime/l04-learning
    if ($LASTEXITCODE -ne 0) { throw '无法读取 B。' }

    $task = $taskText | ConvertFrom-Json
    $event = $task.events | Where-Object { $_.detail -eq '已创建课程隔离 Worktree' } | Select-Object -Last 1
    if (-not $event.evidence.path) { throw 'B 没有可复验的隔离候选。' }

    $candidate = (Resolve-Path -LiteralPath $event.evidence.path).Path
    $output = Join-Path (Get-Location) ('.runtime/l04-check-' + [guid]::NewGuid().ToString('N'))
    & $python -X utf8 $probe --workspace $candidate --output $output --case all --file-entry flowerp.inventory_export:export_inventory_file
    $exit = $LASTEXITCODE
    Write-Host "候选目录：$candidate"
    Write-Host "证据目录：$output"
    Write-Host "退出码：$exit"
    if (Test-Path -LiteralPath (Join-Path $output 'report.json')) {
        Get-Content -Raw -Encoding UTF8 -LiteralPath (Join-Path $output 'report.json')
    }
    if ($exit -ne 0) { throw '库存导出复验失败，请保留报告并打回 B。' }
}
```

报告必须覆盖：

| 检查项 | 合格表现 |
|---|---|
| `normal` | 东仓 8−3=5，西仓 12−4=8；八列、两条明细、排序正确 |
| `empty` | 只有表头，没有数据行 |
| `special` | 逗号、引号、中文和换行读取后不变 |
| `ordering` | 商品、仓库、仓位、批次逐级排序 |
| `file-failure` | 保留旧文件；没有旧文件时不留半成品 |
| 所有情境 | 导出前后库存和业务流水不变 |

复验者还要查看实际 Diff，确认没有密钥、环境文件、运行数据库或范围外修改。将报告路径、退出码、实际发现和未验证项写入 `B-evidence.md`。

**本步通过标准：**复验针对 B 的同一候选，CSV、失败路径、只读性和写集均有证据。

## 第 7 步：接受、打回或返工

### 7.1 独立接受或打回 B

由实际复验者执行：

```powershell
python -X utf8 -m workbench.cli task-review TASK-实际B编号 `
  --runtime-dir .runtime/l04-learning `
  --reviewer '实际复验者姓名' `
  --decision approve `
  --note '已核对 Spec、实际 Diff、CSV、失败路径、只读性和剩余风险'
```

任一检查失败，把 `approve` 改为 `reject`，并写明失败报告位置。不要删除原 B；修复应产生新的候选和新的检查目录。

![执行结束、检查通过和人工接受是三个判断](./assets/diagrams/03-evidence-decisions.png)

*左列回答 Codex 进程怎样结束；中列回答独立 Eval、CSV 和 Diff 是否满足合同；右列才是具名审核者接受哪个版本。超时、越界或检查失败都要停止并留证；即使检查通过，没有审核决定也只能保持待审核。*

### 7.2 判断返工对象

| 观察到的问题 | 应返工什么 |
|---|---|
| CSV 字段、数量、排序或文件保护失败 | 打回 B，引用原报告重新执行 |
| 工作台漏报越界、吞掉失败或状态失真 | 暂停 B，先修复并重新接受 A |
| A 接受后控制源码又变化 | 新建 A，重新独立复验 |
| 没有非执行者或需求确认人 | 保持待审核，不声称完成 |

### 7.3 完成交接记录

在 `lesson-04-submission/handoff.md` 回答：

1. **Codex 如何协作：**A 和 B 中分别做了什么？谁授权、谁复验、谁接受？
2. **产品状态：**库存导出交付了什么真实结果？
3. **工程问题：**哪些越界、自报完成或失败处理风险被暴露？
4. **工作台增量：**V0 如何绑定 Spec、执行、Eval、证据和人审？
5. **学习证据：**A 的独立接受、B 的 Diff、CSV 和失败复验如何证明你能迁移这套流程？

最后记录 A、B 编号，确认版 Spec 的 SHA256，候选目录，实际修改文件，验证命令，审核人、决定和剩余风险。

### 提交前自查

- [ ] A 与 B 是两个可追查任务，B 引用了已接受的 A；
- [ ] B 使用 L03 同一份确认版 Spec；
- [ ] 实际 Diff 落在授权写集内；
- [ ] 库存导出五组情境和只读性都有真实结果；
- [ ] 摘要包含修改文件、验证命令、结果和剩余风险；
- [ ] 密钥、环境文件、运行数据库和生成报告未提交；
- [ ] 自动绿灯没有替代具名人工接受；
- [ ] 失败证据和返工任务没有被删除。

做到这些，才完成了从“直接让 Codex 搭台”到“由工作台组织 Codex 交付 FlowERP”的自举换挡。

- **主题：**委托 Codex 执行一次最小变更
- **核心内容：**非交互执行、工作目录、权限边界、结果采集与人工确认点。
- **演示结果：**读取第 03 讲 Spec，委托 Codex 完成一个小型代码变更并运行测试。
- **课内增量：**完成执行入口和结果摘要；仓库文件由 Codex 在授权工作区直接处理，不额外包装为文件读写 MCP。
- **通过标准：**变更能够运行；基础测试通过；摘要包含修改文件、验证命令和剩余风险；密钥和环境文件未提交。
