# L00｜课前准备：装好工具，跑通第一次环境自检

这张卡是你的操作入口。先读[详细讲义的开篇导读](../L00-课前准备-安装工具与通过环境自检.md)，认识课程和工具，再回到这里逐步操作。遇到不认识的词或报错，打开对应讲义段落查阅。

今天完成四件事即可：**工具能用 → 环境能检查 → 结果能解释 → 记录能提交**。工作台从 L01 开始建设；今天克隆的参考代码只用于准备环境。

## 开始前：安排三段时间

| 次序 | 这一段做什么 | 可以暂停的位置 |
|---|---|---|
| 第一次 | 读导读，安装工具，记录版本 | 行动 1 完成，或已记录安装卡点 |
| 第二次 | 下载仓库，建立环境，运行自检 | 行动 5 完成，或已保存完整报错 |
| 第三次 | 与 Codex 对话，完成练习，整理记录 | 文末提交检查完成 |

不以安装速度评分。下载等待时间因设备与网络而异，不需要一口气做完。每次结束前保存当前步骤、输出和下一步；再次开始时回到自己的课程目录。

**先准备一个记录文件**：有 [空白模板](../labs/L00/SUBMISSION.md)时先另存一份；还没下载仓库时，可先用记事本／文本编辑保存为 `L00-临时记录.txt`。macOS 文本编辑可选“格式 → 制作纯文本”。下载到模板后再把已有记录填进去，不必重新操作。

执行规则：只用自己系统的命令，一次一行；失败后先停下保存信息。若阻塞的是某个工具，可以先读导读、整理记录；依赖该工具的后续动作等解决后再做。

## 行动 1｜安装并记录版本

先按[详细安装步骤](../L00-课前准备-安装工具与通过环境自检.md#l00-install)完成安装，再执行下面的版本检查。

### Windows

```powershell
py -3.11 --version
git --version
code --version
codex --version
```

### macOS

```bash
python3.11 --version
git --version
code --version
codex --version
```

不要只写“已安装”，必须保存真实版本输出。`code --version` 失败时改用 VS Code `帮助 → 关于`，并注明未加入 PATH。某项失败时保留错误信息。

## 行动 2｜克隆课程仓库

Windows 示例：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\work"
Set-Location "$env:USERPROFILE\work"
git clone https://github.com/congde/CodexFDE.git
Set-Location CodexFDE
git status
```

macOS 示例：

```bash
mkdir -p ~/work
cd ~/work
git clone https://github.com/congde/CodexFDE.git
cd CodexFDE
git status
```

**继续前确认**：课程目录中能找到 `pyproject.toml`、`AGENTS.md` 和 `docs/courses/`，`git status` 能识别仓库。资料缺失时联系课程组织者核对发放版本。

Windows 默认使用用户目录下的 `work`，不要求电脑有 D 盘。请选择自己有写权限、不会自动同步到网盘的目录。

### 克隆成功后：只设置本仓库的学习身份

确认 `git status` 已能识别课程仓库，再运行下面两条查询命令（两种系统通用）：

```text
git config user.name
git config user.email
```

没有输出可能只是尚未配置。若显示的身份不是你准备使用的学习身份，或显示为空，再执行下面的设置；已有合适身份可以跳过：

```text
git config --local user.name "你的学习署名"
git config --local user.email "你自己的邮箱"
git config user.name
git config user.email
```

将引号里的文字换成自己的信息。提交时姓名和邮箱会进入历史记录，使用自己愿意公开的学习身份或隐私邮箱，不复制老师的身份。这里的 `--local` 只影响当前课程仓库，不会改动其他仓库。

## 行动 3｜创建 `.venv`

先确认当前目录包含 `pyproject.toml`。新开终端时重新进入行动 2 选择的课程目录；不要在其他目录创建环境。

### Windows

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe --version
```

### macOS

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e .
.venv/bin/python --version
```

两种系统都直接使用 `.venv` 中的 Python，无需激活。每行成功后再执行下一行；最终版本应为 3.11.x。已有 `.venv` 版本不符时保留目录并求助，不重复创建覆盖它。

## 行动 4｜打开课程工作区

在 VS Code 选择“文件 → 从文件打开工作区”，打开：

```text
docs/courses/FlowERP-AI研发工作台.code-workspace
```

打开命令面板（Windows：Ctrl+Shift+P；macOS：Command+Shift+P），搜索 `Python: Select Interpreter`，确认解释器为：

- Windows：`.venv\Scripts\python.exe`
- macOS：`.venv/bin/python`

两种系统都在新终端直接运行行动 5，不点击课程任务按钮；按钮包含后续课程动作，且默认路径按 Windows 编写。

## 行动 5｜运行最小环境自检

不要运行 `serve`、`serve-workbench`、`demo`、`course-status`、`init`、blocking Eval 或 `unittest discover`。

### Windows

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "import sys, sqlite3; print(sys.version); print(sys.executable); print('sqlite', sqlite3.sqlite_version)"
$LASTEXITCODE
.\.venv\Scripts\python.exe -X utf8 -c "import workbench, eval, flowerp; print('imports-ok')"
$LASTEXITCODE
.\.venv\Scripts\python.exe -X utf8 -m workbench.cli --help
$LASTEXITCODE
git status --short
git diff --stat
code --version
codex --version
```

### macOS

```bash
.venv/bin/python -X utf8 -c "import sys, sqlite3; print(sys.version); print(sys.executable); print('sqlite', sqlite3.sqlite_version)"
echo $?
.venv/bin/python -X utf8 -c "import workbench, eval, flowerp; print('imports-ok')"
echo $?
.venv/bin/python -X utf8 -m workbench.cli --help
echo $?
git status --short
git diff --stat
code --version
codex --version
```

`$LASTEXITCODE`（Windows）或 `echo $?`（macOS）显示上一条外部命令的退出码；紧接对应输出保存，0 通常表示成功。

**继续前确认**：解释器路径在当前仓库 `.venv` 内，能看到 `imports-ok` 和命令帮助。Git 两条命令没有输出可以是正常状态；用它们一起查看已有修改与新文件。

这些命令成功只证明环境就绪，不能写“个人工作台已经完成”或“FlowERP 已交付”。

## 行动 6｜完成第一次 Codex 只读练习

在桌面入口打开行动 2 的课程目录；CLI 先进入同一目录再运行 `codex`。两种入口确认能用后，选择一种完成下列对话。后续命令请另开终端，避免发进 Codex 对话框。

发送：

```text
请只读检查当前课程仓库，不修改任何文件，也不运行会改变状态的命令。
告诉我：
1. 仓库根目录路径；
2. Python 最低版本从哪个文件得出；
3. 课程大纲保存在哪个文件；
4. L01 开始时为什么不能假设个人工作台已经存在；
5. 仍有哪些结论你无法仅凭当前证据确认。
请给出可定位的文件路径，不要编造。
```

人工打开至少两个引用文件核验。只打开登录页不算通过。模型回答不能代替你的检查。

## 入门练习与预习

按[讲义第九节](../L00-课前准备-安装工具与通过环境自检.md#l00-practice)完成四个小练习：找到当前目录与版本声明；预测算式结果再运行；观察一次故意的断言失败与退出码；人工核验 Codex 的两个引用。分别记录“独立完成／需提示／未完成”。练习不修改 ERP，也不能当作 L01 的实现证据。

再读 `AGENTS.md` 的项目目标和目录边界，准备一句自己的真实痛点。Python 官方教程作为查阅或延伸，不要求零基础同学课前读懂所有语法。通过标准包含基本操作与判断，安装成功不能替代这些练习。
